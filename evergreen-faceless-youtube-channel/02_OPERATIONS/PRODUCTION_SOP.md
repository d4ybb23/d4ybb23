# Production SOP — The Profit Map

**Purpose:** Produce original, source-backed, rights-aware business documentaries reliably.  
**Applies to:** Every long-form episode, including pilots.  
**Non-negotiable:** No episode reaches public upload without a completed source log, asset log, claim review, and named final approver.

## 1. Workflow at a Glance

| Stage | Owner at launch | Required output | Gate to advance |
| --- | --- | --- | --- |
| 1. Qualify topic | Channel Principal | Topic brief | One non-obvious answer, credible source leads, and an honest packaging angle. |
| 2. Build dossier | Principal or Researcher | Research dossier + source log | Every consequential claim has a traceable source or is removed. |
| 3. Write script | Principal or Writer | 1,800–2,700-word script | Promise appears in first 75 seconds; all numbers are time-qualified. |
| 4. Design visual beat sheet | Principal + Editor | Beat-by-beat visual plan | Original diagrams, maps, or design work carry at least 30–40% of explanatory value. |
| 5. Record narration | Approved narrator | Clean WAV + reviewed transcript | Cadence, pronunciation, and meaning receive human review. |
| 6. Assemble rough cut | Editor | Rough cut + project file | Every visual supports the spoken idea; tempo holds through the first minute. |
| 7. Run quality/rightsm gate | Principal | Completed preflight | No unlogged assets, unsupported claims, or misleading packaging remain. |
| 8. Package and schedule | Principal | Upload package | Title, thumbnail, description, chapters, playlist, end screen, and pin all align. |
| 9. Observe and learn | Principal | 48-hour note + retrospective | One next experiment recorded before the next upload. |

## 3. Topic Qualification Standard

The person qualifying a topic must complete the topic brief before opening a blank script. A strong brief begins with a question that the audience can understand without prior industry knowledge, then defines the real mechanism and what could make the answer more complicated than it first appears.

| Required field | Acceptance standard |
| --- | --- |
| Viewer question | Written in plain English, answerable in one video. |
| One-sentence thesis | Non-obvious, falsifiable, and free of overclaiming. |
| Stakes | Explains why the mechanism matters beyond trivia. |
| Source leads | At least two primary/authoritative sources plus a source for counterarguments. |
| Visual premise | Identifies three or more original explanatory visual opportunities. |
| Packaging promise | One honest title angle and two thumbnail concepts. |
| Kill condition | States what evidence would invalidate the story. |

## 4. Research and Claim Standard

Use primary sources for specific company numbers and formal statements whenever possible: annual reports, securities filings, investor presentations, government data, regulator documents, academic work, direct interviews, and well-attributed investigative or trade journalism. A competitor’s YouTube video is never evidence for a claim. It may be a packaging observation, nothing more.

| Claim class | Evidence required | Script treatment |
| --- | --- | --- |
| Reported financial number | Primary filing or official results release | Name the period and source in the graphics; narrate the period. |
| Company strategy or business-model description | Filing, official corporate explanation, or direct executive statement | Attribute the company’s view and distinguish it from editorial inference. |
| Industry generalization | Multiple credible sources or authoritative dataset | State scope, market, and exceptions. |
| Contested explanation | At least two perspectives | Present uncertainty or narrow the claim. |
| Editorial inference | Evidence chain exists but no source states the conclusion exactly | Use “this suggests,” “one implication is,” or equivalent. |

## 5. Script Standard

The word target for a 12–18 minute episode is **1,800–2,700 words**, but clarity governs duration. The cold open begins with the contradiction; no extended branded logo animation, generic rhetorical question, or verbal throat-clearing is permitted.

| Time window | Narrative requirement | Editorial check |
| --- | --- | --- |
| 0:00–0:25 | Specific contradiction | Could a stranger restate the puzzle? |
| 0:25–1:15 | Promise, stakes, map of the answer | Does the title get fulfilled early? |
| 1:15–3:30 | Context | Is context only included because it changes the mechanism? |
| 3:30–8:00 | Mechanism | Is there an original explanatory diagram? |
| 8:00–12:30 | Trade-off, conflict, or limitation | Does the story avoid a victory-lap simplification? |
| 12:30–15:30 | Resolution and transferable model | Is the opening answered directly? |
| Final 0:30–0:45 | Specific next-view bridge | Is the next video naturally connected? |

## 6. Visual Standard

An editor is not hired to find wallpaper. The visual plan must clarify causality. Build original flows, timelines, maps, data cards, and comparison devices before requesting stock footage. Every use of an archival image, logo, screenshot, or clip receives a source, intended use, license status, and reviewer decision in the asset log.

| Visual type | Correct job | Improper use |
| --- | --- | --- |
| Original diagram | Makes a mechanism visible | Decorative arrows that imply proof without data. |
| Chart/data card | Grounds one narrated claim in time and source | Unlabeled numbers or false precision. |
| Licensed/owned B-roll | Creates texture or physical context | Filling every scene with generic, unconnected footage. |
| Archive/screenshot | Supports commentary, history, or analysis | Replacing original analysis with a clip compilation. |
| Logo/product image | Identifies the subject | Using a logo as permission to use any asset from the brand. |

## 7. Roles and Approval Rights

At launch, one person can hold multiple roles. The approval rights do not move merely because the timeline gets busy.

| Role | May prepare | Must not approve alone |
| --- | --- | --- |
| Channel Principal | Everything | Final public upload if any material legal, factual, or sponsor issue remains unresolved. |
| Researcher | Dossier, source log, claim notes | Thesis, final claims, or script without principal review. |
| Writer | Draft script | Unsourced facts or edits that change the thesis without review. |
| Editor / visual researcher | Beat sheet, rough cut, asset candidates | Asset-rights exception or final factual representation. |
| Narrator | Audio performance | Changes to facts, claims, or persuasion language. |
| Thumbnail designer | Concepts and files | Final public promise without principal choice. |

## 8. Definition of Done

An episode is done only when it has an approved final master, captions, source log, asset log, script, visual beat sheet, upload package, and completed preflight. The public upload is a separate, named decision. Nothing is “basically done” when the source links are missing; that is a draft wearing sunglasses.
